Sequência de eventos

  • Problemas adicionais descobertos nos logs App caiu às 21:09 UTC (build .next apagado durante deploy anterior). StripeAuthenticationError com chave sk_test_ às 21:25 UTC (STRIPE_MOCK=true já estava ativo — sem impacto real).
  • Fix implementado e deployado Commit b825278 pushed para main. GitHub Actions disparado. callbackUrl agora usa URL absoluta via NEXTAUTH_URL com fallback pelo header host.
  • Testes corrigidos e suíte 100% verde 208 testes passando. Unit: 7/7 · Component: 65/65 · Integration: 136/136.
  • Débito técnico identificado e documentado Textos hardcoded em PT no PortalDashboard.tsx e chaves i18n obsoletas — confirmado como descuido de sessão anterior. Documentado em docs/M4-EXECUTION-BACKLOG.md secção 8.

Bug corrigido — Magic link callbackUrl relativo

src/app/api/admin/users/invite/route.ts Corrigido

O redirectTo passado ao NextAuth v5 era relativo. Em produção, isso causa rejeição silenciosa do token, resultando em "link expirado" imediato.

// ANTES — URL relativa → NextAuth v5 rejeita em produção
await signIn("nodemailer", {
  email,
  redirectTo: "/portal?invite_locale=en",   // ❌ relativo
  redirect: false,
});

// DEPOIS — URL absoluta com fallback
const baseUrl = process.env.NEXTAUTH_URL?.replace(/\/$/, "") ??
  `${request.headers.get("x-forwarded-proto") ?? "https"}://${request.headers.get("host")}`;

await signIn("nodemailer", {
  email,
  redirectTo: `${baseUrl}/portal?invite_locale=${locale}`,  // ✅ absoluto
  redirect: false,
});
tests/integration/admin-users-invite-route.test.ts Atualizado

Assertion atualizada para validar padrão de URL absoluta via regex em vez de string hardcoded.

// ANTES
expect(mocks.signIn).toHaveBeenCalledWith("nodemailer", expect.objectContaining({
  redirectTo: "/portal?invite_locale=en",  // ❌ quebrava após o fix

// DEPOIS
const call = mocks.signIn.mock.calls[0];
expect(call[1].redirectTo).toMatch(/^https?:\/\/.+\/portal\?invite_locale=en$/);  // ✅
