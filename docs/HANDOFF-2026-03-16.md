### S6 — Similar Projects Library ✅ NOVO

#### O que faz
Ao analisar um novo briefing, o sistema busca automaticamente projetos anteriores com escopo semelhante e injeta esse contexto no prompt do Gemini. A IA então referencia projetos reais como benchmarks de horas, budget e complexidade, tornando as estimativas progressivamente mais precisas.

#### Decisão de implementação — sem pgvector
A biblioteca pgvector não possui binários pré-compilados para Windows (PostgreSQL 15). Para não bloquear o desenvolvimento, os embeddings são armazenados como `TEXT` (JSON array de 768 floats) e a similaridade coseno é calculada em TypeScript. A migração para pgvector em produção (Linux) requer apenas alterar o tipo da coluna — o algoritmo permanece idêntico.

#### Schema (`prisma/schema.prisma`)
```prisma
model ReferenceProject {
  id              String    @id @default(cuid())
  title           String
  description     String    @db.Text
  projectType     String
  features        String[]
  techStack       String[]
  complexityScore Int
  hoursActual     Int
  budgetRange     String
  briefingId      String?   @unique
  briefing        Briefing? @relation(fields: [briefingId], references: [id])
  embedding       String    @db.Text  // JSON.stringify(float[768])
  createdAt       DateTime  @default(now())
}
```

#### Utilidades (`src/lib/embeddings.ts`)
- `generateEmbedding(text)` — chama `text-embedding-004` (Gemini) com `SEMANTIC_SIMILARITY`, retorna `number[]` de 768 dimensões.
- `buildEmbeddingText(data)` — serializa os campos relevantes do projeto em uma string normalizada para embedding.
- `cosineSimilarity(a, b)` — álgebra pura em TypeScript, sem dependências externas.

#### API endpoints
| Rota | Método | Auth | Descrição |
|------|--------|------|-----------|
| `/api/library/add` | POST | ✅ sessão | Recebe dados do projeto, gera embedding, persiste em `ReferenceProject` |
| `/api/library/similar` | POST | ❌ pública | Recebe texto, compara com todos os projetos, retorna top-N com score ≥ 0.7 |

#### Integração com S5 (`src/app/api/briefing/analyze/route.ts`)
1. Texto do briefing é convertido em embedding.
2. Todos os `ReferenceProject` são carregados e rankeados por cosine similarity.
3. Os 3 mais similares (threshold 0.7) são formatados e injetados no prompt do Gemini como bloco `PROJETOS SIMILARES JÁ ENTREGUES`.
4. Se a biblioteca estiver vazia ou o banco indisponível, o bloco é omitido silenciosamente — sem regressão no S5.

#### Ciclo de atualização
A biblioteca se torna mais precisa à medida que projetos são marcados como entregues no portal e cadastrados via `/portal/biblioteca`. Cada novo projeto melhora as estimativas dos briefings seguintes.

# Handoff complementar — 2026-04-14

## O que foi entregue

### 1. Magic link — reescrita completa do fluxo de convite (commit `4d6b630`)

**Problema raiz:** O código anterior gerava o token manualmente com `randomBytes` e tentava replicar o hash interno do Auth.js (`SHA256(rawToken + AUTH_SECRET)`). Mesmo após a correção do hash, os clientes continuavam recebendo "Link inválido ou expirado". Com PM2 rodando 2 instâncias (`instances: 2` em `ecosystem.config.cjs`), qualquer estado em memória (Map, singleton) também seria inviável.

**Solução:** Delegate totalmente para o Auth.js.

- `POST /api/admin/users/invite` removeu todo código manual de token (randomBytes, crypto.subtle, verificationToken.create/deleteMany).
- Agora chama `await signIn("nodemailer", { email, redirectTo: "/portal?invite_locale=pt", redirect: false })`.
- O Auth.js gera o token, faz o hash correto e persiste automaticamente no DB.
- `redirect: false` evita que `signIn()` lance `NEXT_REDIRECT` dentro de um Route Handler.

### 2. sendVerificationRequest — diferenciação invite vs. login normal

Adicionado `sendVerificationRequest` ao provider Nodemailer em `src/auth.ts`.

**Lógica de detecção:**
- Convite de admin: `callbackUrl` contém `invite_locale=pt|en|es` → template multilíngue personalizado com nome do usuário.
- Login normal (página `/portal/login`): `callbackUrl` sem `invite_locale` → e-mail simples de acesso.

Antes desta mudança, qualquer login normal recebia o e-mail de "Sua conta foi criada e está pronta para acesso" — confuso para quem já era cliente.

### 3. Templates de e-mail extraídos para lib

- Criado `src/lib/email-templates/invite.ts` com `INVITE_COPY` (PT/EN/ES) e `buildInviteEmail()`.
- Tipo `InviteLocale = "pt" | "en" | "es"` exportado e compartilhado entre `invite/route.ts` e `auth.ts`.

### 4. Validação de e-mail na route de convite

Adicionada validação de formato com regex antes do upsert no banco:
```typescript
const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
if (!emailRegex.test(email)) {
  return NextResponse.json({ error: "Email inválido." }, { status: 400 });
}
```
